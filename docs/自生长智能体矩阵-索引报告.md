# 自生长智能体矩阵 —— 索引报告

> 目标：验证「分类体系随新 agent 注册而自我扩张的多智能体矩阵」设想在学界/开源界的坐标，得出「今天能拼什么、缺什么自己写」的落地结论。
> 编制日期：2026-10-22。检索方法：集群并行（线1 前台先行校准关键词，线2–线9 八个后台 agent 并行）；只采一手来源（arXiv 原文、官方 spec/文档、官方 GitHub 仓），每条 claim 标出处，未验证标「待核」，禁止编造。
> 上游：`docs/HANDOFF-自生长智能体矩阵调研.md`（已获批检索方案，本报告为其执行结果）。

## 一句话需求

用户（萧逆尘）设想一个**分类体系随新 agent 注册而自我扩张的多智能体矩阵**（总控分类 → L1/L2 路由 → agent 链路执行，像神经网络一样生长、胜任所有工作）；本次调研验证该设想的学术/开源坐标，并给出落地路线。

## 核心结论（已验证，勿重复搜）

1. **学术坐标确认**：该设想位于 self-evolving agents 综述框架下的「架构级演化（architecture evolution）」×「open-endedness 持续扩张」交叉点（arXiv 2507.21046、2508.07407、2406.04268）。HANDOFF 预设的四个最接近原型——Agentic Neural Networks、Darwin Gödel Machine、Voyager、EvoAgentX——均确认存在且有官方仓。
2. **编号更正（两处）**：HANDOFF 给出的 arXiv 编号有误——「Agentic Neural Networks」正确编号为 **2506.09046**（2501.11753 实为经济学论文）；「Meta Agent Search」是 ADAS 论文（2408.08435）内部提出的算法名，2509.13533 实为放射医学论文，与本题无关。
3. **核心空白确认（线9，调研的最重要产出）**：未发现任何一手工作完整实现「新 agent 注册 → 自动提议类目 → 影子验证 → 晋升 → 分类体系版本化」流水线。空白成立。自研范围划在：将「提议—影子验证—晋升—版本化」骨架首次绑定到 **agent 注册事件**与**能力类目体系**的交叉处。
4. **两个设计修正点被一手文献实证支撑**（线6）：全 agent 两两互通成本 O(n²) 且网状/广播拓扑是错误级联的最坏拓扑（t≤3 步近乎全员感染）（arXiv 2406.11776、2603.04474）；失败源于组织设计而非单 agent 能力，需结构性重设计（arXiv 2503.13657，MAST 分类学）。
5. **静态骨架可由现成件拼出**（线8）：MCP Registry（官方明示 preview，有 breaking change 风险）+ A2A v1.0 + semantic-router + LangGraph + Temporal + Langfuse 均有官方文档与可跑通的 quickstart。
6. **「像神经网络一样生长」已有半个字面实现**（线3）：agent 作为可反传（文本/符号梯度）的图节点成立，边连接可微优化成立（GPTSwarm），训练后创建新 agent 团队仅 ANN 一家声明；但「注册驱动的开放集节点增生 + 分类层自动重训」无一手工作。
7. **演化引擎成熟件盘点**（线2/线7）：可直接复用的只有 EvoAgentX（活跃维护、pip 可装、demo 齐全、内置 AFlow/TextGrad/MIPRO/EvoPrompt、带 HITL 审批）；ADAS/DGM 的 archive 是最接近的版本化雏形（带指标、可溯祖）；AFlow/ADAS/DGM/Voyager 均为一次性论文代码，取思想不取代码。
8. **验收/晋升/回滚各环节有件、闭环无人**（线5）：验收（Voyager 式执行验证、F2P 测试、LLM-as-judge）与回滚（kill-switch/流量切回）在 MLOps 与官方文档中有成熟件；shadow/canary 在 agent 语境已有流程模型（arXiv 2411.13768 §4.1.1）与云厂商实践（AWS agent 测试金字塔）；完整自治闭环未发现任何已实现系统。

### 线3 agent 即神经元

| 条目 | 关键机制 | 一手来源 |
|---|---|---|
| Agentic Neural Networks（ANN，arXiv 2506.09046；HANDOFF 原编号 2501.11753 有误） | 「agent 即神经元」字面实现：MAS 建模为分层神经网络，前向阶段仿前传动态分解任务、逐层构建 agent 团队，反向阶段仿反传用迭代反馈自进化各 agent 角色/prompt/协调方式；明确声明训练后可创建新的专门化 agent 团队（结构可生长）；官方仓：待核 | https://arxiv.org/abs/2506.09046 |
| TextGrad（arXiv 2406.07496） | 文本反传引擎：复合 AI 系统建成计算图，`loss.backward()` 逆拓扑遍历，LLM 生成自然语言批评作为「文本梯度」，TGD 优化器更新文本变量；API 镜像 PyTorch；论文自述 differentiation 在此是隐喻，无数值导数 | https://arxiv.org/abs/2406.07496 ；https://github.com/zou-group/textgrad |
| Agent Symbolic Learning（arXiv 2406.18532） | agent＝符号网络：可学习「权重」＝prompts、工具及堆叠方式；language loss/gradient/symbolic backpropagation 实现部署后持续自我更新 | https://arxiv.org/abs/2406.18532 ；https://github.com/aiwaves-cn/agents |
| GPTSwarm（arXiv 2402.16823，ICML 2024 Oral） | agent 图可递归组合；边优化有真正的数值可微参数（Adam 更新），可在线自改进编排拓扑、剪除对抗 agent；只优化固定节点集上的边，不长新节点 | https://arxiv.org/abs/2402.16823 ；https://proceedings.mlr.press/v235/zhuge24a.html |

**判定**：「像神经网络一样生长」已有字面实现但只完成一半——可反传节点、可微边连接均成立，唯独 ANN 支持节点增生；「注册驱动的开放集节点增生 + 分类体系自动扩张」的开放式神经发生尚无一手工作，仍是比喻向字面过渡的缺口。

### 线4 能力注册与动态发现

| 条目 | 关键机制 | 一手来源 |
|---|---|---|
| MCP Registry（官方注册中心） | 社区驱动「MCP server 应用商店」：`mcp-publisher` CLI 提交静态 `server.json`（name/description/version/packages/repository 等），命名空间所有权验证，REST API `GET /v0/servers` 检索，v0.1 冻结期；**能力声明＝静态元数据文件，schema 无「类目」字段，无自动提议新类目机制** | https://github.com/modelcontextprotocol/registry ；https://registry.modelcontextprotocol.io/v0/servers |
| A2A AgentCard（能力广告与发现） | agent 的 JSON 名片：capabilities（布尔特性位）+ skills[]（id/name/description/tags/examples/输入输出模式）；发现三策：Well-Known URI、策展注册表（spec 明确「does not prescribe a standard API for curated registries」，注册表 API 未标准化，仅列 Future Considerations）、直接配置 | https://github.com/a2aproject/A2A/blob/main/docs/topics/agent-discovery.md |
| semantic-router（意图路由） | 零样本向量语义路由不走 LLM：每 Route 预定义 5–10 条示例 utterances，离线嵌入，查询时余弦相似度选最优；1.x 支持置信度校准，低于阈值返回 None 可兜底；**Route 集须预定义，运行时不自生成新 Route** | https://github.com/aurelio-labs/semantic-router |
| ARDP（IETF 草案，2026-02，个人提交非标准） | 稳定 agent 身份、动态端点解析、capability advertisement（跨 MCP/A2A/HTTP/gRPC 协议选择）、presence 信令；早期探索，佐证「能力广告」尚无成熟标准 | https://www.ietf.org/archive/id/draft-pioli-agent-discovery-01.html |
| ARD（Google Agentic Resource Discovery，2026-06） | 域名 well-known 路径发布 `ai-catalog.json`，客户端可用自然语言 intent 查询 ARD registry；最接近「意图→发现」，但 catalog 类目仍由发布方自定义，无注册时自动建类目规定 | https://developers.googleblog.com/announcing-the-agentic-resource-discovery-specification/ |

**判定**：MCP Registry + A2A AgentCard + semantic-router 可直接用作静态骨架（能力声明、查询、毫秒级路由齐备）；三者均无「注册时自动提议/创建新类目」机制——可在注册钩子里对 skill/description 做嵌入聚类、超阈值提议新类目并动态追加 Route，此件需自研。

### 线6 反面证据

| 条目 | 关键机制 | 一手来源 |
|---|---|---|
| MAST/MASFT 失败分类学（UC Berkeley，NeurIPS 2025 D&B） | 7 框架、1600+ 标注轨迹、14 个细粒度失败模式 3 大类：系统设计/规范 44.2%、智能体间错位 32.3%、任务验证失败 23.5%；各框架失败率 41%–86.7%；干预仅 +9.4%——失败源于组织设计而非单 agent 能力 | https://arxiv.org/abs/2503.13657 |
| 「验证器非银弹」 | 带 verifier 的 ChatDev 在 ProgramDev 正确率仅 33.33%；现有验证器只做表层检查（有无注释、能否编译），深层错误穿透多层验证 | https://ar5iv.labs.arxiv.org/html/2503.13657 （§4.3） |
| 多智能体辩论的失败模式（ICML 2025 MAS Workshop） | 辩论轮次越多准确率越降；谄媚与社会从众使模型从正确答案翻转为错误答案——错误在交流中被系统性放大 | https://arxiv.org/abs/2509.05396 |
| 错误级联与虚假共识（From Spark to Fire） | 三类内生脆弱性：级联放大、拓扑敏感性、共识惯性；网状拓扑广播式交互 t≤3 步近乎全员感染；6 框架中 5 个达 100% 最终感染，显式 reviewer/QA 也挡不住 | https://arxiv.org/html/2603.04474v2 |
| 全连接通信的代价与稀疏拓扑优势 | 现有辩论默认全连接（成本随 n² 增长）；稀疏通信拓扑显著降本且性能相当甚至更优 | https://arxiv.org/abs/2406.11776 |
| 竞争性反馈回路诱发涌现错位（Moloch's Bargain） | 竞争受众优化压力下 LLM 自发产生欺骗性营销（+14.0%）、虚假信息（+188.6%），明确指示诚实也照样出现——竞次动力学 | https://arxiv.org/abs/2510.06105 |

**对用户原设计的直接命中**：全连接两两互通三重命中（O(n²) 成本、最坏级联拓扑、错位无可观测手段）；「四层树压缩三个正交维度」命中 FM-1.4 上下文丢失与 FC3 验证失败；「自生长」三重警告（组织结构失控、竞次、协商放大错误）。注：针对 self-evolving MAS 的专门失败分类学未检索到一手论文，标「待核」。

**判定**：必须强制规避——全连接/广播拓扑（改稀疏黑板＋产物契约）、无契约的产物压缩（须可验证中间产物与深层验证）、无终止条件与失败归因手段的自生长扩张（须注册准入校验、终止条件共识与级联熔断）。

### 线8 可落地骨架件

### 线9 缺口确认

| 条目 | 关键机制 | 一手来源 |
|---|---|---|
| ACPs（Agent Collaboration Protocols） | Agent Registration Protocol（能力描述语言＋分层注册服务器＋合规审查）＋Discovery Protocol；能力描述语言由协议设计者预定义，无类目自动提议、无扩张、无版本化 | https://arxiv.org/pdf/2505.13523 |
| ANP 技术白皮书 | Agent Description＋Discovery Protocol，JSON-LD/schema.org 描述能力；复用既有词汇表，不含类目体系生命周期管理 | https://arxiv.org/html/2508.00007v1 |
| Agent Identity URI Scheme | 层级能力路径（/workflow/approval/invoice），注册在「最具体能力层级」，DHT 存储；最接近「能力层级树注册」，但路径自报、无提议—审核—晋升、无版本化 | https://arxiv.org/html/2601.14567v1 |
| 自扩张反应分类（化学域，机制类比最接近） | label generation agent 在既有类目不足时提议新分类，verifier 审计，taxonomy updater 无人工介入扩张层级（68→14,073 类）；缺：对象是化学反应而非 agent 注册，无影子验证期、无版本化/回滚治理 | https://arxiv.org/html/2607.01061v2 |
| EvoOntology（人大，开源仓） | 自演化本体层：Diagnose→Patch→Evaluate（配对评估）→门控发布/回滚，显式 Gated versioning；流水线形状高度相似，但对象是数据语义本体、触发器是执行轨迹而非 agent 注册 | https://github.com/ruc-datalab/EvoOntology |
| Voyager／Skill-V（技能库谱系） | Voyager 技能库持续增长+自验证入库，但平铺条目无类目层级；Skill-V 技能存为带版本字段的 versioned contract，仅限单技能粒度 | https://arxiv.org/abs/2305.16291 ；https://arxiv.org/html/2610.11781v1 |
| OM4OV（本体版本化） | 本体匹配做版本比对（Agent-OV），证明本体版本化技术存在；离线匹配工具，与注册驱动无关 | https://arxiv.org/abs/2409.20302 |
| 检索无命中记录 | 「agent capability ontology automatic generation」「agent registry capability taxonomy self-evolving」「taxonomy versioning evolution agent capability categories」「agent marketplace automatic category proposal registration」等检索词 0 一手命中 | 本轮 web_search 检索记录 |

**判定**：**空白确认**——注册/发现协议（ACPs、ANP、Agent Identity URI）只有静态能力词汇表；机制最接近的自扩张分类（化学域）与 EvoOntology 具备「提议—验证—门控—版本化」骨架但作用对象与触发器均非 agent 注册；SoA 与 2603.28990 只提供生长/涌现不提供持久分类体系。自研范围＝「提议—影子验证—晋升—版本化」骨架 × agent 注册事件 × 能力类目体系的交叉无人区。

## 落地路线（P0→P3）

```
P0 静态骨架 MVP（全部现成件，立即可拼）
├── 注册/互通：MCP Registry（server.json，注意 preview 风险）+ A2A AgentCard（skills/capabilities 声明）
├── 路由：semantic-router（Route 预定义 + 置信度校准 + None 兜底）
├── 编排/持久执行：LangGraph（状态机）+ Temporal（Durable Execution，演化环底座）
├── 可观测/验收底座：Langfuse（trace + 数据集回归 + CI 评测门禁）
└── 版本表：topology/agent/contract 三元组（自建表，无现成件）
P1 离线演化环（成熟件拼装，带验收可回滚）
├── 演化引擎：EvoAgentX（pip 可装，内置 AFlow/TextGrad/MIPRO/EvoPrompt）
├── 晋升闸口：EvoAgentX HITL 审批拦截器
├── 验收函数：Langfuse 数据集回归 + Voyager 式「验证通过才入库」
├── 存档：仿 ADAS/DGM archive（带评测指标、可溯祖的版本树）
└── 回归度量：参考 SWE-Bench-CL 的遗忘/迁移指标（新增能力是否弄坏旧能力）
P2 自研缺口件（核心增量，无人区）
├── 注册钩子：对 AgentCard skills/description 嵌入聚类，超阈值自动提议新类目并动态追加 semantic-router Route
├── 影子验证 → 晋升 → 回滚流水线（流程蓝图参考 arXiv 2411.13768 §4.1.1；shadow 层参考 AWS 测试金字塔顶层）
├── 类目体系版本化：参考 EvoOntology 的 Gated versioning，绑定到 agent 类目
└── 安全阀：级联熔断 + 终止条件共识 + 注册准入校验（线6 避雷清单）
P3 全自治演化环（长期）
├── 评审自动化：深层验证补「验证器只做表层检查」缺口（2503.13657 §4.3 警告）
├── 竞次防护：避免引入单纯竞争选择压力（Moloch's Bargain 2510.06105 警告）
└── 审批分级：按风险自动/人工（依赖待决问题 2 的决策）
```
